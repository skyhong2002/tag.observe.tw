# 標籤群組

標籤可以歸進群組，一個標籤可以同時屬於多個群組。例如川普同時在「外國政治人物」與「國際」。

群組分兩種（`tag_group_defs.kind`）：

- `group`：舊站的 28 個身分／類型群組，編號沿用舊站 `tag_group`（1 政治人物、2 現任立委、3 現任縣市長、4 民進黨、5 國民黨……24 外國政治人物、25 電視電影、27 網紅、28 六都市長候選人）。
- `topic`：舊站的主題大類，編號是舊站 `catalogue` 加 100（101 政治、102 體育、103 娛樂、104 社會、105 國際、106 生活、107 科技、108 動物、109 健康醫療、110 產業金融）。舊站 catalogue 11–15 是編輯的工作佇列，不是主題，沒有沿用。

管理員在 `/admin/tags/` 的「分類與群組」 可以新增、改名、調整順序、刪除群組，也可以把群組放進同類的另一個群組底下（例如「現任立委」放在「政治人物」底下）。

- **上下層**（`tag_group_defs.parent_id`）：上層群組的公開頁與標籤數包含子群組的標籤；標籤頁上，標籤所在子群組的上層群組也會列出（API 的 source 為 `parent`）。不能把群組放進自己或自己的子群組，也不能跨種類。
- **刪除**：群組定義不真的刪掉，只記 `deleted_at`，所以重跑舊站匯入不會把它建回來；群組裡的標籤紀錄全部移除，子群組往上移一層，之後自動規則也不再寫入這個群組。
- 改名、移動、排序、刪除都記在 `tag_group_def_log`。

## 狀態與來源（`tag_group_members`）

| status | 意思 | 公開 |
| --- | --- | --- |
| `auto` | 規則自動判斷 | 是 |
| `confirmed` | 管理員確認或手動加入，或舊站人工標記 | 是 |
| `review` | 等管理員確認 | 否 |
| `rejected` | 管理員排除，之後自動重跑也不會加回來 | 否 |

| source | 怎麼判斷 |
| --- | --- |
| `legacy` | 舊站資料，由 `tools/tag-groups.ts legacy` 匯入一次 |
| `admin` | 管理員手動加入 |
| `person` | 人物的 Wikidata 資料：國籍、職業、現任政黨（任期名冊不由這條規則填） |
| `wikidata` | 非人物標籤的 Wikidata 項目類型（P31） |
| `section` | 各媒體把帶這個標籤的報導放在哪個版別 |
| `ai` | AI 依近期標題提出的建議，一律列為 `review` |

每條規則重跑時，只換掉自己來源的 `auto` 列；`confirmed`、`rejected` 一律不動。別的來源已有的 `auto` 列，只有分數更高才會被取代。別的規則留下的 `review` 列（例如舊站 2016 年的「現任立委」），若這條規則有把握（例如 Wikidata 顯示仍是現任立法委員），就改為 `auto`；管理員手動加入的 `review` 列不會被改。管理員的每次決定都記在 `tag_group_member_log`。

## 任期名冊（2026-10-16 起）

`CURATED_GROUPS`（`rules.ts`）：2 立委、3 縣市長、14 縣市議員、18 內閣、19 北市府、28 六都市長候選人，以及之後為新任期新增的名冊。

- 以任期開始的年份命名，例如「2024 立委」（第 11 屆立法院）、「2022 縣市長」；新的任期另開一個名冊，舊的保留。
- 名單依中選會、立法院、行政院、臺北市政府等官方資料整理，含補選、遞補、代理，成員一律是 `admin` 來源的 `confirmed`；同名的人逐一確認後才加入。
- 自動規則（人物、Wikidata、AI）不寫入名冊；讀者的「改關係」頁不出題也不接受提案（API 回 409）。
- 「看寫法」以群組 id 對應身分（`writing/people.ts`），改名不影響。

## 舊站資料

- **`tag_group_log`（1,845 筆，人工標記）**：取自 2026-09-26 的唯讀快照（`~/tag-analysis-private/group-snapshot/selected.sql`）。
  - `del_flag=1` 的不匯入。
  - 「現任立委」「現任縣市長」「內閣」「北市府」「六都市長候選人」是 2016–2022 年標的，可能已經過時，匯入為 `review`。
  - 其他群組匯入為 `confirmed`。
- **`catalogue_tag`（2016 年 6–8 月）**：舊站排程依版別算出來的，不是人工標記。
  - 每個標籤取占比 30% 以上的最多兩個主題，匯入為 `auto`。

匯入用 `INSERT IGNORE`，已經存在的列（管理員決定過的、規則先寫的）不覆蓋。

## 自動規則（`app/src/tag-groups/`）

1. **人物**（`rules.ts` 的 `personGroups`）
   - 對象：頭像流程比對到的人物（`tag_people`），以及 Wikidata 步驟發現是人類（P31=Q5）的標籤。
   - 是不是同一個人，沿用頭像流程的判斷（`findPerson`）：只是別名或暱稱的（「鳳山」「恆春」）略過；有同名人物的列為 `review`。
   - 規則：
     - 台灣國籍的政治人物歸「政治人物」，其他國籍的歸「外國政治人物」。
     - 職位不再用來歸類：立委、縣市長、議員、內閣是任期名冊（見下方），由官方名單整理。
     - 現任政黨對應民進黨、國民黨、時代力量、親民黨。
     - 演員、歌手、主持人依國籍歸「藝人」「中港藝人」「外語藝人」，台灣歌手另歸「歌手樂團」；政治人物不歸藝人群組，因為 Wikidata 把川普也列為演員。
     - 運動員歸「運動明星」或「外國運動員」，YouTuber 歸「網紅」，非政治人物的企業家歸「商場經理人」。
2. **版別**（`sectionTopic`、`voteTopics`）
   - 取近 90 天帶這個標籤的報導，用 `articles.category`，或網址前三段路徑，對應主題。
   - 中文版別名稱用子字串比對；英文只比對完整單字，避免 `pet` 誤中 `competition`。
   - **每家媒體一票**，依它各版別的篇數分配，所以鉅亨網上千則台股快訊也只算一票。
   - 至少 3 家媒體有版別資料；主題占比 30% 以上、且至少 2 家媒體放在該主題，才算數。每個標籤最多兩個主題。
3. **Wikidata 類型**（`typeGroups`）
   - 取名稱或別名與標籤完全相同、Wikipedia 條目最多的項目，結果存在 `tag_wikidata`，30 天內不重查。
   - 只看直接類型，例如上市公司→公司廠商、政府機關→政府部門單位、電影或電視劇→電視電影、政黨→政治、疾病→健康醫療、職業體育聯盟或球隊→體育。
   - 一般名詞常和作品或公司同名（「失聯」是電視節目），所以除非近期的主題也落在預期範圍（例如電視電影要有娛樂），否則列為 `review`。核對時不看舊站 2016 年的版別統計，除非管理員確認過。
   - 查過的標籤，重跑時直接用 `tag_wikidata` 裡的類型重新判斷；人物的資料沒有快取，30 天後才重查。

4. **AI 補漏**（`ai.ts`）
   - 前三條規則跑完後，還缺身分群組或主題的標籤，連同最近 30 天至多 4 則標題，每 20 個一批送到共用的 ai-gateway（OpenAI 相容的 `/chat/completions`，預設模型別名 `sky-fast`）。
   - 回覆只收清單裡有的群組編號；建議一律列為 `review`，管理員確認前不公開。分數記 0，所以不會取代其他來源的 `auto` 列。
   - 問過的時間記在 `tag_wikidata.ai_checked_at`，30 天內不重問。
   - 設定：`TAG_AI_BASE_URL`、`TAG_AI_API_KEY`、`TAG_AI_MODEL`（預設 `sky-fast`）。沒有 key 時略過這一步。

順序是人物 → 版別 → Wikidata → AI：版別要先跑，Wikidata 類型才查得到主題；AI 只處理前面沒分到的。

worker 每天 04:55（`TAG_GROUPS_CRON`，排在 04:40 的人物頭像之後，頭像會先比對出新的人物標籤）對本週新聞排行前 500 個標籤跑一次（`jobs/tag-groups-job.ts`）。Wikidata 與 AI 只問 30 天內沒問過的標籤，平常一天只有幾十個新標籤；worker 同時跑兩個工作、鎖 15 分鐘，所以這個工作最多跑 10 分鐘，時間到就在標籤之間停下，剩下的留到隔天。

## 執行

```sh
# 舊站資料（一次）
node --env-file=.env tools/tag-groups.ts legacy ~/tag-analysis-private/group-snapshot/selected.sql ~/tag-analysis-private/legacy-2026-10-04/core.sql.gz
# 本週排行上的 500 個標籤：人物、版別、Wikidata、AI
node --env-file=.env tools/tag-groups.ts auto --top 500
# 只跑某一步、或指定標籤
node --env-file=.env tools/tag-groups.ts section 台積電 颱風
```

`--force` 讓 Wikidata 與 AI 步驟重查 30 天內問過的標籤。

## API

- `GET /api/v1/tags/{tag}/groups`：標籤所屬的群組與主題（只回傳 `auto`、`confirmed`）。
- `GET /api/v1/tag-groups`：群組一覽與各群組的標籤數。
- `GET /api/v1/tag-groups/{id}`：群組裡的標籤，一次 1000 個。

詳見 [api.md](api.md)。

## 前台

- 標籤頁標題旁列出標籤的群組（實心）與主題（外框），連到群組頁。
- `/group/`：每個群組與主題一張卡片，列出最近 1、7 或 30 天報導最多的 5 個標籤（細長條依卡片內第一名縮放）、上新聞的標籤數、篇數合計與和前一段的增減；沒有標籤上新聞的群組列在最後一行。資料來自 `/api/v1/tag-groups/overview`，一次算完所有群組，伺服器保留 10 分鐘。
- `/group/{id}/`：群組（含子群組）裡最近 1、7 或 30 天達到關鍵字排行第一道門檻（24 小時內至少兩家新聞媒體各標了兩篇以上，`tag_stats` 第 2 級）的標籤，依報導篇數排序，和再之前同樣天數比較，可依篇數或增減排序。只從過了門檻的標籤算，是因為直接從 `article_tags` 算「生活」這種上千個標籤的群組要十幾秒。

## 統一標籤管理

`/admin/tags/` 是共用管理入口：分類與群組、文章關係、人物頭像、其他標籤圖像。舊的 `/admin/tag-groups/`、`/admin/writing/`、`/admin/avatars/`、`/admin/tag-visuals/` 會保留查詢參數並導向對應分頁。

分類適用於人物、機構、地點、事件與概念。同一標籤可屬於多個分類；分類也可有上下層。編輯分類與查詢文章關係之間，可帶同一個 `tag` 切換。

### 與「看寫法」共用分類

`tag_group_defs.writing_role` 將角色／背景分類對應到「看寫法」既有的統計類別，改名不會改變對應。子分類繼承上層的對應；純主題分類不會因此成為人物身分。新增更細的角色分類時，可放到適合的角色／背景分類下。

管理員確認或排除相關分類時，在同一個交易內更新 `writing_people` 的分析快取與已辨識該對象的 `article_writing`。移動或刪除分類也會重算受影響成員。統計類別仍維持既有 API 的穩定鍵；多個分類對應到同一統計類別時只計一次。分類全被排除時列為「尚未標記」，自動分析不會把人工排除的分類加回。

migration `0037_unified-tag-management.sql` 建立缺少的角色分類，並將舊 `writing_people` 的人工修正匯入共用分類，保留原修改人與時間。既有 confirmed/rejected 決定透過 INSERT IGNORE 保留，並依共用分類重新對齊舊人工修正的分析快取與文章分類。舊修正紀錄留在 `writing_people_log`；之後的分類決定統一寫入 `tag_group_member_log`。舊的 `PUT /auth/admin/writing/people/:name` 回傳 409 與新管理網址，避免快取中的舊介面另寫一份分類。

### 文章關係與證據

管理員限定的 `GET /auth/admin/tags/:tag/articles` 列出同一標籤的文章關係，每頁 30 篇，以 `next` 傳給 `before` 取得下一頁；同篇有多種關係仍只佔一列。

- `tagged`（文章標籤）：文章目前的 `article_tags` 資料。這不能當成內文提及、發言或作者的證據。
- `retold`（被轉述）：`article_writing` 已辨識的轉述對象，附原文判斷句、平台及規則版本；不會由共用分類推斷此關係。

此版本不推斷一般「被提及」或「作者」關係。作者、機構署名與來源署名需各自辨識，不能把原始署名一律當成同名人物標籤。原文過期後，已儲存的轉述判斷句仍可查閱。
