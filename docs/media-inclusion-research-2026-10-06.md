# 媒體收錄範圍研究：語言版本、台灣受眾與國際稿源

研究日期：2026-10-06（Asia/Taipei）。本報告是收錄政策與入口研究；沒有改動爬蟲、排行、資料庫或線上顯示。

## 研究結論

**決策單位應是「來源的特定版本與內容用途」，而不是整個媒體品牌。** 對本站而言，台灣讀者可直接閱讀的新聞比較、外電引用追蹤、海外媒體研究與歷史保存，是不同用途。使用一張刪除名單同時控制這四件事，會丟失有價值的資料，也無法解決重複稿、版本混收及錯誤入口。

最重要的新發現是：**路透社有持續更新、公開可讀的繁體供稿頻道，值得優先補入。** 目前本站設定只抓英文圖解存檔，不能代表路透對台灣中文讀者的實際供稿。法新社也有官方合作方列出的中文產品，但本輪尚未驗證到能獨立、穩定取得近期稿件的專屬入口。美聯社則已確認有台灣媒體引用與編譯使用，不能因此聲稱 AP 原站有公開繁體綜合新聞版。

建議採用的預設政策：

- 台灣新聞及專業媒體持續收錄；依主題參與比較，不要求每家都報政治。
- 外國媒體的合適中文版本保留比較資格；新增至固定排行前先驗證版本、內容與涵蓋率。
- 中國、港澳、新馬及其他海外媒體另有可選範圍；不以所在地、繁簡體或政治立場直接刪除。
- 英日文原文保留國際稿源與研究用途，不預設當作與中文同等涵蓋的詞頻樣本。
- 聚合入口與原始供稿者分開，停止抓取與刪除歷史分開。

## 路透、法新、美聯：查清楚的是什麼

### 路透社：應修正入口，而不是排除品牌

[中央社產品頁](https://www.cna.com.tw/about/product.aspx)明列「路透社 -- 網路中文即時新聞」，說明中央社與路透合作供應全球華文讀者。[Reuters 官方文字供稿頁](https://reutersagency.com/content/content-types/text/)另列 12 種語言和語言新聞線，但該頁本身沒有證明哪個公開端點提供繁體。（E01、E02）

本輪找到並實讀 [LINE TODAY 路透社頻道 101170](https://today.line.me/tw/v3/publisher/101170)，確認近期有大量繁體文章。以下三篇的 `provider` 都是「路透社」、正文有路透電頭、結尾有中央社翻譯／編譯署名，時間來自該頁 `datePublished`：（E05–E08）

| 文章 | 刊登時間（台北） | 署名關係 |
| --- | --- | --- |
| [科技股回落，華爾街股市開平盤](https://today.line.me/tw/v3/article/5yvpMDr) | 2026-10-05 21:45 | 路透紐約電；中央社編譯 |
| [挪威擬禁止特定場所戴 AI 眼鏡](https://today.line.me/tw/v3/article/EXwBp5Q) | 2026-10-05 21:22 | 路透哥本哈根電；中央社翻譯 |
| [法國海上救援移民船](https://today.line.me/tw/v3/article/mWp090e) | 2026-10-05 20:29 | 路透巴黎電；中央社翻譯 |

另核對 [OpenAI 募資報導](https://today.line.me/tw/v3/article/vXLN5EE)，同樣有路透電頭與中央社翻譯，正文還引述彭博，顯示一篇文章可能有多層來源。（E09）

**「不是 Reuters 原站」不等於「不是可收錄的路透中文稿」。** 合作平台可以是有效刊登入口，但要同時保存平台、供稿者、翻譯者與明示引用。

目前本站 `reuters` 的有效入口是 `graphics.thomsonreuters.com`，既有 audit 樣本是 2024 年英文圖解；本輪近 31 天公開文章 API 為 0 筆。這只能說這個查詢範圍沒有收錄，不是路透沒有近期新聞。

建議：保留 `reuters` 媒體身分與既有引用關係；把英文 Graphics 標成該品牌下的特定內容版本，新增繁體合作供稿版本。完成正文、日期、歸屬及去重驗證後，繁體供稿可參加中文事件比較與下一版固定排行。

接入前有兩個已驗證的細節，不能省略：

1. LINE 文章的 JSON-LD `articleBody` 是帶省略號的短摘要，頁面才有完整正文；不能直接把該欄位當全文。
2. [2025-02-04 瑞典清真寺報導](https://today.line.me/tw/v3/article/DR9Bpao)的頻道及 provider 都寫路透社，但正文電頭是法新社。這是一篇舊稿反例，不代表近期全頻道都有問題；卻足以說明「provider=路透」不是原稿出自路透的充分條件。（E10）

本研究確認的是公開頁面的供稿標示與可讀性，未查閱平台或通訊社間的非公開合約。

### 法新社：中文供稿有依據，獨立近期入口仍需驗證

中央社產品頁明列「法新社 -- 英文新聞、網路中文即時新聞」，包括國際、財經、科學及運動等內容。該頁包含年代較早的公司與產品敘述，因此不能單憑它認定每條服務目前的合約或技術端點。（E01）

[AFP 官方介紹](https://www.afp.com/en/about-us)列一般供稿六種語言，以及另有多語言事實查核網路。一般供稿語言清單沒有中文，**不否定合作方供應的中文產品**；查核產品也不能代替完整國際新聞線。（E03）

本站 `afp` 現在抓 `factcheck.afp.com` 英文查核，本輪五筆均是英文查核標題。另有 [中央社 2026-10-04 報導](https://www.cna.com.tw/news/aopl/202610040006.aspx)，本站已存正文有「法新社報導」及中央社編譯署名，API 也保留 `cna → afp` 引用證據。（E11）

建議：保留 AFP 身分；現有英文查核標明「AFP Fact Check（英文）」的收錄範圍；中文新聞優先沿正式刊登來源保存譯稿與 AFP 來源關係。本輪**尚未驗證到獨立、持續更新且歸屬一致的 AFP 繁體專屬入口**，不把 Reuters 頻道那篇 AFP 舊稿當成已解決入口問題。

### 美聯社：引用角色已確認，不假設有公開繁體原站

中央社產品頁列代售美聯社英文新聞，以及國外新聞中心選譯外電的服務。[AP 官方](https://www.ap.org/content/formats/newswires/)提供文字新聞授權。（E01、E04）

本站現在抓 AP 官網 News Highlights，五筆近期樣本包括一般文字報導及兩篇標题含 photos 的圖集。不能把這個樣本視為 AP 全部新聞產出，也不能把圖集一律說成完整文字報導。

[中央社 2026-09-30 科技報導](https://www.cna.com.tw/news/ait/202609300024.aspx)有中央社記者署名，內文明示引用美聯社；本站 API 歸 `cna` 並保留 `ap` 引用。這證明台灣中文新聞實際使用 AP，而不是 AP 原站繁體版存在的證明。（E12）

建議：保留 AP 作為重要稿源；台灣媒體編譯／引用的文章照刊登身分保存，另標示 AP 關係。公開繁體綜合新聞入口本輪未核實，不作「AP 沒有任何中文服務」的絕對結論。

## 簡體、繁體與主要服務對象的具體分組

### 明顯以中國新聞市場為主的現有簡體入口

`guancha` 觀察者網、`thepaper` 澎湃、`news_qq` 騰訊、`news_sina` 新浪、`news_163` 網易、`ifeng` 鳳凰網、`cctv` 央視、`people_cn` 人民網、`huanqiu` 環球網、`xinhuanet`／`xinhua` 新華網／新華社。本輪樣本均可直接看到簡體標題。

建議歸入可選「中國來源」，有助觀察兩岸敘事、跨媒體引用與相同事件的差異；不預設把中國地方新聞的發稿量混成台灣媒體關注度。新華社的國際通訊社角色仍保留。這不表示它們沒有台灣讀者，或所有內容都與台灣無關。

`taiwan` 中國台灣網另列「兩岸／中國來源」：目前從新浪官方帳號取得簡體稿，但部分傳播目的面向台灣，不能寫成「完全不是寫給台灣人」。

### 海外簡體中文不能全部視為中國媒體

- `zaobao` 聯合早報：本站五筆簡體，官方定位為新加坡與全球華人，首頁有簡繁切換及新加坡／國際／中國三種版本。建議「新加坡／國際華文」，不是純中國來源。（E21、E22）
- `sinchew` 星洲網：本站五筆簡體；本輪官網實際可顯示繁體並切換簡體。主要內容是馬來西亞新聞。建議「馬來西亞華文」，不能稱只提供簡體。（E23）
- `voachinese`、`rfa`、`soundofhope`、`secretchina`：本站本輪標題樣本為簡體，但所在地、編輯定位與中國本地平台不同。先分為國際中文／海外華文；有繁體版本的來源須另驗證入口，不以反對或支持哪個政府作收錄條件。

### 有繁體版，也不一定是台灣專版

BBC 中文、RFI 中文、DW 中文、日經中文、NYT 中文、NHK、共同社、韓聯社都有中文新聞參考價值。對於本輪已直接驗證的繁體入口，記錄於 E13–E20。特別是：

- BBC 繁體首頁有台灣分類與近期台灣報導，與 `bbc_global` 英文版是不同版本。
- NYT「關於我們」同時描述中國讀者與全球中文讀者；繁體入口不等於台灣專版。
- 共同社與韓聯社的繁體內容依然有大量日韓國內新聞；適合國際／日韓事件比較，是否進入台灣本地事件計數要看事件及範圍。
- 韓聯社的繁體網址含轉換閘道；這不自動表示另有一套台灣編輯室。
- 日經繁體頁的 html lang 仍是 `zh-cn`；星洲官網在本輪顯示繁體，但爬蟲收的是簡體。不能只取 html lang 當真實語言。

香港01、明報、星島、東網、香港文匯、大公文匯、中評社、澳門日報、正報，以及世界新聞網，適合依主要服務地區分組。中評社有台灣採訪，本輪最新樣本即包含台中議會；不能粗略說它完全不面向台灣。端傳媒及香港成立的生活／科技媒體，也不能因註冊地就排除：例如 The Femin 本輪樣本有台灣活動，流動日報的內容可直接服務繁體科技讀者。

Taipei Times、Taiwan News、Focus Taiwan、TaiwanPlus 是「台灣外語」的重要對照：內容主題與台灣直接相關，但受眾包含外籍及國際讀者，不能把「台灣媒體」「繁體內容」「台灣人閱讀」當成同一個概念。

## 聚合、供稿、翻譯：不要只看文章所在網域

前面討論把 Yahoo 與 Google 新聞、LINE TODAY 一起概括成聚合平台，對目前程式而言不夠精確：

- Google 新聞及動態網已是 `discovery` 來源，不擁有文章列。它們近 31 天文章查詢為 0，不能據此說沒有在工作。
- Yahoo 有原創也有轉載；目前 `yahoo` 覆寫設定以 `provider: 'Yahoo'` 限定自家內容。應保留符合條件的 Yahoo 編輯採訪，不能把它整家排除。
- LINE TODAY、MSN、蕃新聞、PChome、Miin、鄉民晚報需逐篇辨識是自製、代刊、摘要還是外連。品牌層面的平台分類，不足以推定每篇稿件都沒有原創。
- GQ、Cheers 已有透過 LINE 指定供稿者抓取的先例；新接入 Reuters 繁體供稿可參考這種入口驗證，但還要處理本輪發現的電頭衝突。

建議一篇文章至少能區分：**刊登平台、標示供稿者、翻譯／編譯者、明示引用來源**。若原發稿者有獨立證據，再另記原稿關係；不能由首次收錄時間或最早刊登時間猜原作者。

例如同一篇路透稿由中央社翻譯、刊在 LINE：平台是 LINE，提供者依頁面記路透，翻譯者是中央社；它不是「LINE 自己採訪」，也不該只因翻譯署名就失去路透身分。相反地，中央社自己署名、綜合多家外電寫成的報導，仍是中央社刊登文章，附上各項引用證據。

比較目的也要分開：

- 「哪些媒體刊過」可保留不同刊登者的曝光紀錄。
- 「有多少獨立採訪／原稿」不能把同一通訊社稿的多次代刊當多個獨立消息源。
- 「同一媒體報了幾篇」不重複算同稿簡繁版本、平台別名或相同 canonical URL。

| --- | --- | --- |
| 能否排程抓取 | `crawl/registry.ts`、來源 group、`crawl-disabled.json`、部署停用變數 | 停抓不等於刪歷史，也不等於目錄消失 |
| 媒體頁／目錄 | `v1/media-stats.ts`、名稱圖示表與 `excludedMedia` | 停用來源仍可能列在目錄；excluded 會影響可尋找性，不適合拿來代表「非預設」 |
| 關鍵字排行 | `ranking-baseline.json`、`ranking-basis.ts` | 使用凍結 111 來源的 `all`，不是所有爬蟲自動加入 |
| 事件 | `jobs/events-job.ts` | 熱度詞使用固定 `all` 榜；候選文章又依即時分類名單選取。榜外來源仍可能進入事件報導集合 |
| 文章／標籤／涵蓋率 | 各 API 與分類／媒體條件 | 必須逐項採用同一個比較範圍，不能只改目錄排序 |
| 相似度與引用 | `similarity/compute.ts`、`attribution.ts` | 文字相似與明示引用是兩種證據；外語原文與中文譯文不一定有高字面相似度 |

**最初列出的 TechCrunch、BBC 英文、CNN、SCMP、Yahoo 日本、Reuters、AFP、AP，目前八者都不在固定排行的 categories 名單內。** `ranking-baseline.coverageFrom` 有 TechCrunch 的時間，不表示 categories 已將它納入。相反地，Taipei Times 和 on.cc 在 `all` 固定名單內，反而需要檢討語言或版本範圍。這推翻了「先把八家從主要排行移出」的原先假設。

目前相似度正規化使用 NFKC、大小寫及字元清理，不是跨語言翻譯比對；不能因未配對到英文 AP 原文，就推論中文媒體沒有使用 AP。繁簡轉換若加入檢索與去重，可保留原文並增加比對表示，但不能把轉成繁體當成已符合台灣受眾定位。

固定排行若改來源，要建立新的版本與生效日，核對分子、分母、歷史比較與涵蓋起點，不能悄悄替換舊榜名單再接續同一條趨勢。事件中的媒體數、報導列表、關注度與圖表篩選也需同步定義。

## 保留方式：建議不要先做大量刪除

| 狀態 | 何時使用 | 保留內容及呈現 |
| --- | --- | --- |
| 持續收錄、預設比較 | 已驗證的主要服務來源及版本 | 正常媒體頁、搜尋、事件與對應主題比較 |
| 持續收錄、可選比較 | 海外、外語、較專門的研究來源 | 可搜尋、可選入比較；標示語言、版本和實際收錄範圍 |
| 保留稿源身分，按需取得 | 重要但不能穩定抓全文的通訊社等 | 保留引用節點、證據、名稱與官方連結；不以零收錄當零發稿 |
| 停止定期抓取、保留歷史 | 已停刊、失效入口或暫不投入成本的來源 | 既有文章 ID、原 URL、刊期、版本、引用／相似度關係保留；標示原因 |
| 隔離或修正錯誤資料 | 錯誤歸屬、舊文誤判日期、分類頁當新聞、域名被接手後的垃圾內容 | 先排除統計，保留修正紀錄；需要實際清除時另做影響盤點 |

這裡的保留歷史不等於永久公開全文。本站公開內文目前有刊登後 7 天的可讀期限，保存層另有冷資料歸檔機制；分類變更不能順便改掉這些規則，也不能承諾所有舊文全文一直可讀。

TechCrunch 與 Yahoo 日本不需要因為「不適合預設」就立刻停抓：可先移至／標記為外語延伸來源，觀察使用與引用價值。若要減少抓取成本，再按實際用途決定降頻或停抓；本輪沒有量測各來源資源成本，不假定它們最耗資源。原網域失效或被接手的 overdope、停刊蘋果日報則按歷史來源處理，不把新站內容接到舊品牌底下。

## 建議執行順序

1. **先補正資訊**：在媒體資料中區分品牌與版本，標出 Reuters Graphics、AFP Fact Check、AP News Highlights 的真實範圍；保留三家通訊社身分。
2. **驗證 Reuters 繁體候選入口**：以頻道 101170 做持續抽樣，驗證完整正文、原始時間、路透電頭及中央社翻譯欄位；來源衝突稿先標記待判定。這是本輪最有明確收益的新入口。
3. **修正已見品質問題**：CNN 購物入口、NYT 版本重複、新華兩個 ID 同 URL、NHK 混收、DW 版本，以及歷史頁時間疑點。先保留原記錄，不直接批次刪除。
4. **建立範圍選擇**：至少區分「台灣媒體」「國際中文」「海外華文」「台灣外語／其他外語」及平台角色。這些標籤可重疊；「供稿通訊社」不應被迫和語言、地區擇一。
5. **另版啟用比較基準**：在有連續涵蓋證據後才更換固定榜，事件和篇數統計同步採用範圍；預設可聚焦台灣媒體，國際事件可加入適合的中文供稿。比較媒體刊登與比較獨立稿源要提供不同計數。
6. **最後評估成本才停抓**：有引用價值的來源可保留身分並按需擷取，低使用且不符定位的來源才轉歷史。無須為了畫面乾淨先永久刪除。

後續驗收可採連續 7–14 天抽樣，檢查語言、原始刊期、供稿身分、正文完整性、重複與漏收。這是建議的驗證程序，**本輪尚未執行長期涵蓋測試**。AFP 繁體獨立入口、AP 是否有可用的正式繁體合作 feed、各媒體實際台灣讀者占比，以及來源級成本，仍是已界定的未確認事項。

本次研究的具體建議是：**保留品牌與證據，優先選對版本、修好歸屬與重複，再調整預設比較範圍。路透社繁體稿是應補入的明確例子，不是應刪除的例子。**
