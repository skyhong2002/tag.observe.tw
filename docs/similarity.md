# 新聞內文、相似度與引用

`/similarity/` 比較不同媒體的新聞內文，提供相似文章對照、署名、媒體關係圖與明示引用來源／國家。`/media/<media>/` 整合媒體報導與內文列表，可依刊登時間篩選、以收錄順序分頁；舊 `/media/<media>/articles/` 會保留分頁參數導向這個入口。`/article/<id>/` 顯示已保存的文章文字，支援字級調整及返回原列表位置。新聞標題與圖片連往站內閱讀頁，只有標示外連圖示的原站連結會開啟外部網站。讀取這些頁面不會再要求原站回應，因此原站下架後，刊登 7 天內的文章仍能在站內閱讀。

## 抓取與保存

- 既有 index → article 爬蟲流程對每篇文章擷取正文，包括 RSS 已提供標籤的文章；文章排程亦逐批補抓最近 90 天內收錄但未處理的文章。每家來源的原有節流與批次上限維持不變；每批保留 20% 名額給最早的待抓文章，避免持續新增文章餓死舊文補抓。
- JSON-LD Article.articleBody 與各站正文容器提供內文；不以標題、description 或任意整頁文字冒充正文。排除廣告、相關新聞、圖說及導覽。
- 署名依站方欄位保存，可能是具名記者、編輯、通訊社或編輯部，不保證是人名，也不合併同名人物。
- `body_status`：ok（足夠比對的正文）、short（實際文字較短）、missing、blocked、error、expired；未嘗試的列為 not_fetched。擷取成功不代表能驗證付費版或其他版本是否另有更多文字。
- HTTP 429 停止該批次；一般請求失敗一小時後重試一次；missing／blocked／error 正文六小時後可再嘗試，正文嘗試最多三次。無法存取、付費限制、刪文或版型改變會留下缺口，不能保證任一未來頁面都可抓取。已失敗的版型修正後，可針對指定文章重設抓取狀態再補抓。
- 對外只提供刊登後 7 天內的正文（2026-10-04 使用者決定，`PUBLIC_BODY_WINDOW_MS`）：內文 API、媒體列表與記者頁在期限外一律回 `status: expired`、`body: null`、字元數 0、`expiresAt` 為刊登後 7 天，與真正清除的正文無法區分，網站文字也只提 7 天。相似度與記者比對仍讀資料庫裡的全文，對外只露出最多 100 字的相同片段。
- 儲存仍依使用者 2026-10-03 指示，由取得全文的時間起算 90 天，再由每日 retention 清除；原有 description 仍依發佈日起算，文章標題／來源連結仍保留。頁面區分「過期清除」與「尚未取得」。保留期限可在 `retention-job.ts` 調整。
- 新增 nullable 欄位的 migration `0009_article-content.sql`，以及媒體內文庫分頁索引 `0010_content-pagination.sql`、重試計數 `0011_content-retries.sql`；先遷移資料庫，再啟動新版本 gateway/worker。

```sh
npm run db:migrate
npm run similarity:audit -- --limit 2 --output artifacts/similarity/audit.json
npm run similarity:backfill -- --media cna,udn,ltn --limit 100 --hours 2160
```

audit 只讀公開原站，不寫 DB、不啟用來源。backfill 使用與排程相同的冪等流程，只補尚未處理／符合重試條件的文章。新版本 worker 持續接續補抓；第一次補抓期間，頁面會誠實顯示尚未處理數量。

## 比對方式

演算法版本 `body-shingle-v1`。文字先 NFKC 正規化、轉小寫、移除標點與空白，切成不重複的連續五字片段。Dice 相似度為 `2 × 共同片段數 / (A 片段數 + B 片段數)`。內文至少 200 正規化字元、100 個不重複片段；配對需至少 100 個共同片段並存在至少 20 字連續相同文字。預設相似度 0.65，可選 0.5–1。

正規化全文相等才標記「內文相同」，其餘符合門檻為「高度相似」。另呈現 containment（共同片段／較小集合），不將這個數字當成逐字抄寫比例。只比較不同媒體；不使用標題推定正文相似，不進行跨語言語意／翻譯比對。

### 全量索引（2026-10-04）

使用者要求每一篇新聞都要能查到、每家媒體同樣處理，並保留每天的相似與引用資料，不再只看最近 7 天的抽樣。原本 API 在請求時取最新 10,000 篇（約一天）現場計算、只回傳 2,000 對；現在改由 worker 增量建立永久索引，頁面只讀取結果。

- **比對範圍**：每篇可用正文都與「刊登時間前後 7 天內」其他媒體的全部文章比對（`PAIR_WINDOW_MS`），排除「內容」聯播來源。每篇只在進入索引時比對一次，與先前已索引的文章逐一配對，因此每一對只算一次，晚到的補抓文章也會與既有文章比對。
- **候選搜尋**（`app/src/similarity/minhash.ts`）：五字片段先雜湊成 32 位元整數，每篇計算 128 個 MinHash 值，再以 64 個 band × 2 列做 LSH。共用任一 band 的文章成為候選，再以 128 個值估計 Jaccard，≥ 0.2 才進入精確比對。Dice 0.5 相當於 Jaccard 1/3，此時漏抓機率約 0.05%；預設 0.65 低於百萬分之一。以 2026-09-30～10-02 的 19,565 篇實測，舊的精確倒排索引找到 7,409 對，MinHash 全數找到、沒有遺漏。精確倒排索引兩天就用掉 1.6 GB 記憶體，MinHash 每篇只需 512 bytes。
- **精確分數**：候選一律用上面的 `body-shingle-v1` 對保存的正文重新計算 Dice、containment 與相同片段，所以公開的分數與舊版相同，sketch 只決定要比哪些配對。
- **保存**：`similarity_pairs` 永久保存 Dice ≥ 0.5 的每一對（分數、片段數、≤100 字相同片段、兩篇刊登時間與媒體；`day` 為較晚刊登者的台北日期）。讀取時再依門檻過濾。`article_citations` 保存每篇明示引用的媒體。`article_sketches` 每篇一列，記錄正規化長度與 sketch；正文 90 天後清除時，sketch 也一起清空，但這一列與配對、引用都保留，所以舊期間的統計不會消失。
- **排程**：worker 每 10 分鐘（`SIMILARITY_INDEX_MINUTES`）取最新、尚未索引的正文，每批 2,000 篇、最多 5 批。每批讀取前後 7 天已存的 sketch（約 14 萬篇、72 MB），約 1 秒完成。`articles.similarity_at` 標記已索引，可中斷、可重跑。一次補齊既有資料：`node --env-file=.env tools/similarity-index.ts`（2026-10-04 補齊 61,208 篇，約 30 秒，得到 21,777 對）。
- **讀取**：`/api/v1/similarity` 接受 `hours`（1–168）或台北日期 `from`／`to`（最多 31 天）。伺服器讀出期間內門檻以上的全部配對，算出同題報導組（連通群組，只供瀏覽）、直接比對連線與各媒體篇數。文章證據由 `/api/v1/similarity/evidence` 分頁、篩選與搜尋，不再把全部配對送到瀏覽器。`/api/v1/similarity/daily` 提供每日統計（來源分類以最多 31 天分批讀取配對與署名，限制記憶體使用），`/api/v1/articles/{id}/similarity` 提供單篇的他站相似報導。結果快取 1 分鐘，日期區間快取 10 分鐘。
- 兩篇刊登時間相隔超過 7 天不會比對；正文已在 90 天保存期限後清除的文章，無法再與新文章比對。

## 稿源線索分類（2026-10-06）

相似度演算法與永久配對索引不變，不需要重算正文或資料庫遷移。讀取結果時以 `relation.ts` 統一判定：

- `attributed`：一方明示引用另一媒體，或兩篇都有相同的明示來源。
- `same-byline`：沒有上述來源線索，但整理後有相同的人名署名。組織署名不算共同人名；記者頁移除名單不影響公開原始署名的比對。
- `unattributed`：沒有辨識到上述線索，不等於未授權或抄襲。

每對另保留共同人名、彼此引用旗標、共同來源與標示刊登先後。同署名不保證同一人，明示引用不證明授權、全文轉載或最初原作者。分類優先序為明示來源、同署名、未辨識稿源，因此有同署名且引用中央社的 MSN 稿歸入 `attributed`，畫面仍顯示同署名。

媒體圖只使用直接量測的配對，依同署名、明示來源與刊登先後分類；甲／乙、乙／丙的配對不會產生甲／丙連線。連通群組的 `sourceId` 保留相容欄位，但只是展示代表，不能當稿源；證據項目的 `sourceId` 是直接比對的另一篇。`earliest`／`later` 與每日的 `copied`／`copying` 相容欄位改為未辨識稿源配對的標示刊登較早／較晚，排除同署名、有明示來源、相差不到一分鐘與首次收錄時間尚未確認的配對。

媒體篇數與每日來源分類依文章去重，每一配對只屬一類，但同篇可與不同文章形成不同類別，因此各欄篇數不可直接相加。連線分類計配對數；引用仍計文章數。證據 API 可用 `relation=attributed|same-byline|unattributed` 篩選（指定時只列相似配對）；`direction` 僅影響引用。記者統計保留同署名優先的既有規則，另計其餘已有明示來源的文章，兩者的配對不計較早或較晚。記者表格的相近、較早、較晚、同署名與已註明來源均依所選期間內文章 ID 去重；同署名配對兩端都在期間內時兩篇都計入，各欄可重疊，不可相加。API 的 pairs 與 identical 仍保留配對數供文章對照使用。

Liveboard 同組只產生一張跨站對照卡，以 `copy:<story.key>` 去重；只展示有直接配對且兩側有正文的文章。「幾乎照登／改寫」改為「內文相同／高度重疊／部分重疊」，只有正規化全文相等才標內文相同。兩側標為刊登平台，同時刊登不強選先後，附上共同署名與來源線索。

## 延伸閱讀（`/article/<id>/`）

2026-10-04 使用者要求每則新聞下方列出同一題的其他報導。閱讀頁內文之後的「延伸閱讀」依序列出：所屬事件、他站相似報導（上面的全量索引）、其他媒體的相關報導（最多 8 篇、每家最多 2 篇）、同一媒體的其他相關報導（最多 5 篇），以及相關關鍵字（附前後 3 天的媒體數與篇數）。API：`/api/v1/articles/{id}/related`（`app/src/v1/article-related.ts`）。

- 候選是刊登前後 3 天內與本篇共用標籤的文章。每個標籤依 IDF 加權：`ln((期間文章數 + 1) / (用到此標籤的篇數 + 1))`，所以「杜承哲」（6 篇）遠重於「蔣萬安」（940 篇）或「2026九合一選舉」。分數是共用標籤的權重和，加上 15 × 標題字元雙字 Dice；同分時，刊登時間較接近的排前面。
- 共用 3 個以上標籤即列入；只共用 2 個時，標題至少要有一點相近（Dice ≥ 0.05）；只共用 1 個時，標題要明顯相近（≥ 0.25）。例如「罹難」＋「直升機」會把尼泊爾土石流連到辛巴威直升機墜毀，這條規則把它排除；同樣只共用「辛巴威」的同題報導則保留。
- 標題 Dice ≥ 0.8 視為轉載，只列第一篇；已在「他站相似報導」出現的文章不重複列出。
- 事件：前後一天內、主要標籤與本篇重疊的 event thread。至少共用 2 個主要標籤，或共用標籤的權重達本篇最稀有標籤的 75%，所以只共用「2026九合一選舉」這類常見標籤時不歸入事件。
- 沒有標籤的文章找不到候選，頁面會說明原因。

## 記者頁（`/journalist/`）

- 署名欄位照站方原文保存，記者頁另以 `app/src/journalists/names.ts` 整理成人名或筆名：拆開「、，／」與空白分隔的多人署名，去掉記者／編譯／文等職稱、聯合報／中央社等前綴、「台北2日電」「綜合外電」等電頭，再以媒體名稱（favicon 目錄、attribution 別名）、部門（中心／組／編輯台）、職稱、地名、數字與機構用字過濾。責任編輯、核稿等非作者職稱整筆略過；無法辨認的形狀一律捨棄，寧可漏掉筆名，也不把部門當成人。同名不同人不會分開。
- 索引頁依期間列出每人刊登媒體與篇數；相似統計取自同期間、同門檻的全量索引，頁面標示已比對篇數。「較晚」指自家文章比他站相似文章晚至少一分鐘刊登；對方也署同一名字的配對另計為「同署名跨站」，不算較晚或較早。
- 個人頁列出此人期間內的文章（最多 1,000 篇），以及索引為其中每篇已比對文章保存的全部他站相似配對（與前後 7 天內其他媒體的全部文章比對，排除「內容」聯播來源）。頁面揭露已比對與尚待比對篇數。每篇文章列出站方署名原文、正文字元數、明示引用與他站相似篇數。
- 相似不等於抄襲：同一份新聞稿、通訊社稿、授權轉載與註明引用都會讓內文相近，刊登時間以各站標示為準。頁面用同一句說明（`SIMILARITY_CAVEAT`），先後關係一律中性灰色標示為「對方較早／本篇較早」，個人頁依刊登時間排序，不依「對方較早」的數量排序，避免變成可疑度排名。API：`/api/v1/journalists`、`/api/v1/journalists/{name}`。
- 移除請求（2026-10-04）：記者頁是由公開署名自動整理，不是本人建立的檔案。個人頁「關於這一頁」與索引頁提供預填的 GitHub issue「記者頁移除請求」，頁尾也有「聯絡與移除請求」。不需要人工處理：gateway 每 10 分鐘（`JOURNALIST_REMOVAL_SYNC_MINUTES`）讀 GitHub issues，標題符合「記者頁移除請求：<名字>」且沒有 `rejected` 標籤的 issue 一律生效，不論開啟或關閉；`names.ts` 依 `journalistKey` 比對，之後索引、個人頁、共同署名連結與 API 都不再從署名產生這個人（個人頁回 404，API 快取在名單變動時清除，SSR 頁最多再延遲 5 分鐘）。誤報或惡意 issue 加上 `rejected` 標籤即恢復。`app/data/journalist-exclusions.json` 是不依賴 GitHub 的固定名單。署名欄位原文、文章與原站連結不變。

## 媒體關係儀表板

媒體 tag 選單只列出本期資料在目前藍綠分類、媒體數上限及關係模式下有關係資料的選項。選取分類後，依分析篇數挑選分類媒體，再納入其直接連線對象，保留跨分類引用與相似關係；對象不計入分類媒體數上限，並且仍須符合藍綠篩選。圖與文章證據只呈現至少一端是所選分類媒體的關係，不擴展對象的其他連線。切換條件後若已選 tag 不再有關係資料，會回到「全部 tag」，同步清除媒體選取與證據分頁。

`/similarity/` 以整個視窗內的媒體關係圖為主，支援整張畫布拖曳平移與慣性滑動、依游標位置連續平滑縮放，以及依雙指實際距離縮放（同時支援雙指平移）。圖示和名稱維持可讀尺寸，縮放只改變它們在視野中的位置與間距。縮放範圍為 0.2–20 倍，提供放大、縮小、重設視野按鈕；偏好減少動態效果時停用縮放緩動與慣性。全螢幕按鈕使用瀏覽器 Fullscreen API，不支援時改用填滿視窗的模式，可按退出按鈕或 Escape 返回；媒體節點不可單獨拖曳，切換關係模式或明暗主題保留視野。只選用在全部關係中有連線的媒體；沒有連線者仍可由媒體列表查看。畫布可延伸至頁面兩側，不受一般文章頁的最大寬度限制。桌面與手機一律顯示本期所有有連線的媒體，不設數量上限或數量選單，舊網址的 `mediaCount` 參數不再限制顯示。初始視野自動容納整張圖，重設視野會回到完整總覽；縮放與視窗尺寸只影響視野，不增減媒體。篇數與文章證據涵蓋期間內全部文章。

預設總覽由每家媒體挑選最強的兩條連線合併，節點可能因其他媒體選中而顯示超過兩條。弱連線仍保留在資料中，hover 時展開目前畫面內該媒體在所選關係類型的全部連線，其他媒體淡化；離開後回到總覽。「顯示全部連線」可隨時還原目前媒體之間的全部關係。這些顯示切換不影響引用篇數、配對證據或節點位置。

依連線權重做決定性的 modularity 分群，各群使用無矩形邊界的彈簧引力與節點斥力排列，再依圓形範圍自然聚集；座標採固定世界尺度，視窗縮放只改變視野，避免所有媒體擠向同一中心。方向僅在排版分群時忽略，引用箭頭與證據保留原方向；群組不代表立場或所有權。三種關係模式共用依全部關係選定的媒體、座標與圖示大小，切換只更新連線，即使某媒體在該模式沒有連線也保留原位。每個圖示都常駐顯示無底色的媒體名稱，不因重疊而自動隱藏；名稱字色沿用 `app/data/media-catalog.json` 的既有 blue／green 分類，未標記者使用一般字色；hover 時無關媒體的名稱淡化但仍保留。節點使用本機快取的媒體 icon，圖檔失效時改用文字圖示。

圖示面積隨本期納入樣本篇數增加，桌面尺寸限制在 20–46 px，手機為 16–28 px；僅被引用而未收錄內文的媒體固定為桌面 24 px／手機 18 px，並在 hover 說明不具發稿量資料。節點碰撞間距納入各圖示尺寸，避免大圖示遮蓋鄰近媒體。連線寬度依引用篇數／相似配對數，以對數尺度映射為 1–8 px；切換關係模式沿用同一尺度，hover 保留原本粗細。Hover 顯示媒體國家、引用其他媒體篇數、被其他媒體引用篇數及內文相近篇數，分別依文章 ID 去重。同篇引用多個來源時，來源分項相加可大於總篇數。點選節點或連線展開文章證據；媒體列表提供鍵盤與觸控替代入口。期間、門檻、涵蓋率與方法說明收進側欄。

## 來源與圖例

- 青綠色無箭頭線：同署名跨站刊登。橘色箭頭：未辨識稿源配對的較早刊登方 → 較晚刊登方，不能判定誰引用誰。
- Yahoo provider 欄位中的「姓名｜Yahoo名人娛樂特派記者」視為署名，姓名拆至作者欄位；自家編輯室／頻道合併到 Yahoo，不建立自我引用。未知 provider 必須有媒體組織線索才建立來源，不能以人名創建媒體節點。既有資料以 `node --env-file=.env tools/repair-provider-credits.ts` 預覽，加入 `--apply` 可修正，保留正文與有效引用。
- 紫色箭頭：明示來源 → 引用方，保留證據句。引用對象也可能是中間轉述來源，不保證最初原作者。
- 國家是媒體所屬地區，並非事件發生地、記者國籍或報導來源國。未知媒體標示未知，不靠地名猜測。
- 早發表不等於原創；共同新聞稿、通訊社稿與轉載授權都可能產生重疊。
- 沿用指定 thread 的 29 家基準；「內容」聯播來源蕃新聞可有限抽樣驗證，但不因此啟用整站抓取，也不混入相似度獨立媒體統計。

### 關係圖的顏色與箭頭（2026-10-06）

- 紫色：明示來源／引用，箭頭由來源指向引用方；共同引用第三方沒有彼此引用的箭頭。
- 橘色：未辨識稿源的直接相似配對，箭頭由較早刊登方指向較晚刊登方，僅表示時間先後。同一分鐘或時間未確認不畫箭頭。
- 青綠色：共同人名署名的跨站配對，無箭頭；即使有明示來源，也優先使用此視覺分類。
- 相同媒體之間依視覺分類與方向分開彙整；已有直接引用的配對不重複畫相似線。同署名配對對應的引用線改由青綠線呈現，引用篇數統計仍保留。
- 點選線條時，證據 API 的 `edgeRelation`、`edgeDirected` 會篩選該線實際包含的直接配對。

記者表新增「未見相近」篇數：只計已比對且沒有達門檻配對的期間內文章，同署名配對兩端都排除；不代表原創。各數字欄顯示占本人總篇數的百分比與比例條，可切換篇數／比例排序，並依關係、最低篇數、最低比對覆蓋率與指定欄位比例範圍交叉篩選。媒體篩選僅選記者，不改變其統計範圍。

記者表以單行顯示篇數與比例，比例線不另占高度；刊登媒體最多顯示兩家，完整列表保留於提示與個人頁。可切換「列表／媒體樹狀」：樹狀依各記者期間內篇數最多的媒體分組（同篇數以媒體代碼決定），每人只出現一次；媒體依名稱排列，子列沿用篩選與篇數／比例排序，支援逐組展開與全部收合。
