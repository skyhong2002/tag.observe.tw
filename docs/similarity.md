# 新聞內文、相似度與引用

`/similarity/` 比較不同媒體的新聞內文，提供相似文章對照、署名、媒體關係圖與明示引用來源／國家。`/media/<media>/` 整合媒體報導與內文列表，可依刊登時間篩選、以收錄順序分頁；舊 `/media/<media>/articles/` 會保留分頁參數導向這個入口。`/article/<id>/` 顯示已保存的文章文字，支援字級調整及返回原列表位置。新聞標題與圖片連往站內閱讀頁，只有標示外連圖示的原站連結會開啟外部網站。讀取這些頁面不會再要求原站回應，因此原站下架後仍能閱讀保留中的版本。

## 抓取與保存

- 既有 index → article 爬蟲流程對每篇文章擷取正文，包括 RSS 已提供標籤的文章；文章排程亦逐批補抓最近 90 天內未處理的文章。每家來源的原有節流與批次上限維持不變；每批保留 20% 名額給最早的待抓文章，避免持續新增文章餓死舊文補抓。
- JSON-LD Article.articleBody 與各站正文容器提供內文；不以標題、description 或任意整頁文字冒充正文。排除廣告、相關新聞、圖說及導覽。
- 署名依站方欄位保存，可能是具名記者、編輯、通訊社或編輯部，不保證是人名，也不合併同名人物。
- `body_status`：ok（足夠比對的正文）、short（實際文字較短）、missing、blocked、error、expired；未嘗試的列為 not_fetched。擷取成功不代表能驗證付費版或其他版本是否另有更多文字。
- HTTP 429 停止該批次；一般請求失敗一小時後重試一次；missing／blocked／error 正文六小時後可再嘗試，正文嘗試最多三次。無法存取、付費限制、刪文或版型改變會留下缺口，不能保證任一未來頁面都可抓取。已失敗的版型修正後，可針對指定文章重設抓取狀態再補抓。
- 正文與原有 description 相同，發布超過 90 天後由每日 retention 清除，文章標題／來源連結仍保留。頁面區分「過期清除」與「尚未取得」。保留期限可在 `retention-job.ts` 調整。
- 新增 nullable 欄位的 migration `0009_article-content.sql`，以及媒體內文庫分頁索引 `0010_content-pagination.sql`、重試計數 `0011_content-retries.sql`；先遷移資料庫，再啟動新版本 gateway/worker。

```sh
npm run db:migrate
npm run similarity:audit -- --limit 2 --output artifacts/similarity/audit.json
npm run similarity:backfill -- --media cna,udn,ltn --limit 100 --hours 2160
```

audit 只讀公開原站，不寫 DB、不啟用來源。backfill 使用與排程相同的冪等流程，只補尚未處理／符合重試條件的文章。新版本 worker 持續接續補抓；第一次補抓期間，頁面會誠實顯示尚未處理數量。

## 比對方式

演算法版本 `body-shingle-v1`。文字先 NFKC 正規化、轉小寫、移除標點與空白，切成不重複的連續五字片段。Dice 相似度為 `2 × 共同片段數 / (A 片段數 + B 片段數)`。內文至少 200 正規化字元、100 個不重複片段；配對需至少 100 個共同片段並存在至少 20 字連續相同文字。預設相似度 0.65，可選 0.5–1。

正規化全文相等才標記「內文相同」，其餘符合門檻為「高度相似」。另呈現 containment（共同片段／較小集合），不將這個數字當成逐字抄寫比例。只比較不同媒體；不使用標題推定正文相似，不進行跨語言語意／翻譯比對。

API 最多回溯 168 小時，取最新 10,000 篇可用正文，使用片段倒排索引找候選，回傳前 2,000 對。`sample` 顯示截斷、配對上限（`pairLimit`）與實際比對數量。Graph 相似邊亦只彙整回傳配對，引用邊只反映這批樣本；不是全站、全時期或全部文章的調查。請求結果快取一分鐘，共用同條件計算。比對在獨立 worker thread 執行，單次計算後釋放倒排索引；最多一個同時計算、合計八個執行／等待請求及 25 秒單次執行上限，避免阻塞 API。正文不透過 similarity API 傳出，僅有最多 100 字相同片段；單篇 content API 另提供保留中的文字。

## 媒體關係儀表板

`/similarity/` 以整個視窗內的媒體關係圖為主，不啟用圖內捲動縮放。只選用在全部關係中有連線的媒體；沒有連線者仍可由媒體列表查看。畫布可延伸至頁面兩側，不受一般文章頁的最大寬度限制。預設依實際畫布寬高決定媒體數量，優先保留樣本較多者及其關係來源；設定也可手動選擇 20／40／60／80 家或全部。小螢幕未顯示的媒體仍可在媒體列表查看，篇數與文章證據維持完整樣本。

預設總覽由每家媒體挑選最強的兩條連線合併，節點可能因其他媒體選中而顯示超過兩條。弱連線仍保留在資料中，hover 時展開目前畫面內該媒體在所選關係類型的全部連線，其他媒體淡化；離開後回到總覽。「顯示全部連線」可隨時還原目前媒體之間的全部關係。這些顯示切換不影響引用篇數、配對證據或節點位置。

依連線權重做決定性的 modularity 分群，各群在獨立區域內使用彈簧引力與節點斥力排列，避免所有媒體擠向同一中心。方向僅在排版分群時忽略，引用箭頭與證據保留原方向；群組不代表立場或所有權。三種關係模式共用依全部關係選定的媒體、座標與圖示大小，切換只更新連線，即使某媒體在該模式沒有連線也保留原位。每個圖示都常駐顯示無底色的媒體名稱，不因重疊而自動隱藏；名稱字色沿用 `app/data/media-catalog.json` 的既有 blue／green 分類，未標記者使用一般字色；hover 時無關媒體的名稱淡化但仍保留。節點使用本機快取的媒體 icon，圖檔失效時改用文字圖示。

圖示面積隨本期納入樣本篇數增加，桌面尺寸限制在 20–46 px，手機為 16–28 px；僅被引用而未收錄內文的媒體固定為桌面 24 px／手機 18 px，並在 hover 說明不具發稿量資料。節點碰撞間距納入各圖示尺寸，避免大圖示遮蓋鄰近媒體。連線寬度依引用篇數／相似配對數，以對數尺度映射為 1–8 px；切換關係模式沿用同一尺度，hover 保留原本粗細。Hover 顯示媒體國家、引用其他媒體篇數、被其他媒體引用篇數及內文相近篇數，分別依文章 ID 去重。同篇引用多個來源時，來源分項相加可大於總篇數。點選節點或連線展開文章證據；媒體列表提供鍵盤與觸控替代入口。期間、門檻、涵蓋率與方法說明收進側欄。

## 來源與圖例

- 無方向實線：新聞文字高度重疊；不能判定誰引用誰。
- Yahoo provider 欄位中的「姓名｜Yahoo名人娛樂特派記者」視為署名，姓名拆至作者欄位；自家編輯室／頻道合併到 Yahoo，不建立自我引用。未知 provider 必須有媒體組織線索才建立來源，不能以人名創建媒體節點。既有資料以 `node --env-file=.env tools/repair-provider-credits.ts` 預覽，加入 `--apply` 可修正，保留正文與有效引用。
- 虛線箭頭：刊登媒體 → 內文明確引用的媒體，保留證據句。引用對象也可能是中間轉述來源，不保證最初原作者。
- 國家是媒體所屬地區，並非事件發生地、記者國籍或報導來源國。未知媒體標示未知，不靠地名猜測。
- 早發表不等於原創；共同新聞稿、通訊社稿與轉載授權都可能產生重疊。
- 沿用指定 thread 的 29 家基準；「內容」聯播來源蕃新聞可有限抽樣驗證，但不因此啟用整站抓取，也不混入相似度獨立媒體統計。
