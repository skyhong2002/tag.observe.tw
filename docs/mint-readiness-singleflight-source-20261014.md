# Readiness concurrency and exclusive retry source preparation

The existing mock reproduced one pending readonly identity query with first HTTP200 and concurrent HTTP503. This is a definite source concurrency defect. It is not a confirmed diagnosis of the retained batch001 interruption: the actual outer readiness failure was generic, and its private cause was not recorded. The matched SM before-next lease was paused/apiReadyfalse with378ms age, so that recorded failure was not an expired lease. No batch was retried for this preparation.

The handler now joins at most eight waiters only after each independently verifies its current private receipt, source, bridge/runtime, loopback and actual DB connection identity. Literal receipt bytes, runtime identity and stable dedicated query/metadata/cancel adapter functions must match. It shares only a pending readonly query, never a completed result or old cache. Different identity, waiter saturation and timeout quarantine fail503. All waiters share the original bounded timeout and one cancellation; a late result cannot turn a timed-out response green. A new query is allowed only once result/query/cancellation have safely settled. Each waiter rechecks source/bridge/runtime/receipt and expiry after await. Real cancellation can destroy the dedicated identity connection: restoring it remains an explicitly authorized owner action, not an automatic DB reconnect or shared-pool mutation.

Optional `onDiagnostic` is an owner-supplied enum sink. It receives only schema/phase/reason, without exception text, stack, SQL, connection metadata, credentials or user data. HTTP errors remain generic. The owner must wire a bounded private0600 sink; this source change does not create a file, start a service or claim that diagnostics are already wired. Sink errors cannot expose private errors through HTTP.

A smaller change without API restart is not established: this handler is already loaded in the running Node process, and independently timed Mint/SM consumers cannot reliably serialize one another by adjusting a poll interval. This patch does not modify guard/retry behavior. The owner must review/pin new control source and separately obtain admission for loading the revised private API source/receipt, then use actual readiness evidence. No API was restarted here.

`plan.attemptSuffix` is optional, default empty, and permits `-r2` through `-r999`. It rejects r0/r1, leading-zero forms, nonstrings and path characters. Mint/SM job, admission, controller lease, capture/profile output and frontdoor config namespaces append the suffix; all new writes remain exclusive. Catalogue/session identity remains batch001 and the same four routes. Input/plan/source hashes and explicit receipt suffix bind attempts. The old batch001 directories, admission/config/receipts and immutable APP677 / BUILD Pmj / f166 /761 artifact are preserved. Preparation does not authorize `-r2`, candidate, capture, restart or deployment.
