# 編輯找題與標籤狀態

`/ranking/?order=growth` 提供「正在發酵」模式；原本的熱門排行仍以爆發力排列。頁面兩種模式都預設不限媒體，切換分類或模式也重設為不限媒體，避免新聞分類的嚴格門檻讓小分類全空；手動篩選、排序及顯示更多會保留明確選擇。文字雲在發酵模式按升溫量取詞與調整字體大小。API 不帶 `gate` 的發酵請求仍維持既有 `early` 預設。

分類導覽以不帶門檻的熱門排行摘要判斷收錄狀態，明示無近期報導或暫無關鍵字；摘要不查趨勢、相關詞或相似稿。門檻排除資料時，頁面底部提供不限媒體的候選詞數與解除門檻入口，並區分沒有報導、沒有標籤、沒有正升溫與歷史不足。模式、門檻、字級與計算方式說明統一留在頁底「本頁的資料來源與計算方式」。

關鍵字後方只附新上榜、首次收錄、跳升、歷史不足等標記，沒有獨立狀態欄；升降溫由數值呈現，不另顯示升溫中、降溫中或持平標籤。模式與媒體門檻直接排列，沒有外層框。相似稿資訊列在媒體之後的獨立欄位，包含比對覆蓋，保持單行。

熱門文字雲取分數最高的最多 500 個候選詞；發酵文字雲只取符合門檻的正升溫詞。畫布高度與字級曲線依候選詞數調整，減少小型詞集留白；頁面顯示候選詞數，實際顯示數仍依版面容納量。兩種模式字級各自縮放，不直接比較不同指標的字體大小。

- 升溫量＝爆發力－正規化分數，只有正值列入發酵榜；歷史不足保留未知，不當作零。
- `gate=all`：不限媒體；`early`：至少 2 家各有 2 篇；`broad`：至少 3 家、2 家各有 2 篇、1 家有 3 篇。先篩選全部已保存候選詞，再排序、套用筆數上限；門檻共用 `tag-qualification.ts` 的新聞標籤統計規則。
- 新上榜沿用完整、同基準的 24 小時前快照判斷；與首次收錄不同。
- 首次收錄只描述現存帶標籤文章的收錄紀錄，並檢查最早刊登日期，避免補收舊文章變成新題。先使用 `tag_published` 索引讀最早一筆；已存在舊報導的詞不彙總全部歷史。只有近期候選詞查最早收錄時間。標籤可能在文章收錄後才取得，不聲稱精確的標籤取得時間或網路首次出現。
- 跳升比較現在與 24 小時前是否達到所選門檻；不限媒體時採早期線索。舊榜截斷且未保存此詞、基準不相容或缺少快照時不宣稱跳升。
- 相似稿群採 0.85 內文相似度，兩篇都必須帶此詞、在同一 24 小時視窗及同一固定媒體名單內。相似篇數依文章 ID 去重、配對合併為連通群，並列比對覆蓋；不推定獨立稿源、轉載或抄襲。只讀截止時間前已收錄及已計算的證據，歷史查詢仍以現存標籤紀錄回算。

API：`/api/v1/ranking?category=news&order=growth&gate=early&signals=1`。`signals` 始終提供成長與門檻判斷；`signals=1` 另附首次收錄及相似稿證據。關鍵字狀態 API 與頁面也提供這些資訊。證據查詢採 60 秒、最多 32 筆的按資料庫快取。

Demo 使用獨立 gateway 與 Next dev。若工作目錄的固定媒體基準與現有資料庫不同，可透過 `TAG_RANKING_BASELINE_FILE` 指向經核對的固定名單；不修改來源資料與既有快照。僅移除媒體的新版基準可從舊快照各媒體篇數重算，新增缺少的成員仍視為歷史不相容。

驗證：`app/src/v1/ranking-discovery.spec.ts`、`app/test/ranking-discovery.spec.ts`、既有排行、媒體基準、標籤統計與 API 文件測試。前端及 API 共用的參數解析以 `.mts` 提供給不同 module 設定的專案。
